# Core Loop and Player Feel

## Core loop

```txt
accelerate
→ steer
→ jump
→ avoid obstacle
→ collect reward
→ build combo
→ go faster
→ survive
→ repeat
```

## Desired player feel

The game should feel:

```txt
fast
responsive
risky
readable
skillful
satisfying
```

It should not feel:

```txt
floaty
random
sluggish
unfair
overcomplicated
visually confusing
```

## Emotional rhythm

Runtime Rush should create this rhythm:

```txt
calm control
→ rising speed
→ sudden danger
→ quick decision
→ near miss
→ reward
→ confidence
→ greed
→ bigger danger
```

## Movement feel

Movement should feel momentum-based, not instant and rigid.

The correct feeling is:

```txt
I have momentum, but I am still responsible for control.
```

## Jump feel

Jumping should be:

- responsive
- readable
- useful
- connected to speed

Higher speed can increase jump distance or reward, but jumps should not become uncontrollable in version 1.

## Obstacle feel

Obstacles should test:

```txt
timing
positioning
speed control
```

Examples:

- ground obstacle: jump timing
- side obstacle: steering/positioning
- gap: speed and jump timing
- dense cluster: Focus Mode or Patch Pulse opportunity

## Score feel

Score should reward:

- speed
- survival
- near misses
- clean jumps
- risky collectibles
- Patch Pulse clears
- Overclock runs

Do not reward passive play too heavily.

## The 60-second test

The first prototype should be judged by this question:

```txt
Is skating, steering, jumping, and avoiding obstacles fun for 60 seconds with ugly placeholder graphics?
```
