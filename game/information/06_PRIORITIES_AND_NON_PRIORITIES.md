# Priorities and Non-Priorities

## Highest priorities

### 1. Game feel

Movement must feel good.

This is more important than menus, art, or portfolio cards.

### 2. Clarity

The player must understand:

- where they are
- how fast they are going
- what is dangerous
- what can be collected
- when abilities are available
- why they crashed

### 3. Fairness

Obstacles should be avoidable and readable.

Failure should feel earned.

### 4. Scope control

Build a small fun game, not a giant unfinished game.

### 5. Maintainable code

The code should be modular enough that the AI or developer can safely modify it later.

## Medium priorities

- visual polish
- sound effects
- portfolio card unlocks
- accessibility settings
- responsive layout
- hard mode
- local best score
- mobile controls

## Low priorities for version 1

- online leaderboard
- multiplayer
- account system
- advanced procedural generation
- complex animation system
- many characters
- custom asset packs
- advanced physics
- story mode

## Strict non-priorities

Do not build these in the first version:

- grappling hook
- full platforming levels
- combat system
- inventory system
- RPG upgrades
- dialogue system
- full tutorial campaign
- database-backed game progress
- monetization
- social sharing features

## Decision rule

When deciding whether to add something, ask:

```txt
Does this make momentum skating more fun?
Does this improve clarity, fairness, or replayability?
Can it be built without destabilizing the project?
```

If the answer is no, do not add it yet.

## Feature priority order

```txt
1. Movement sandbox
2. Jumping
3. Basic obstacles
4. Collision
5. Score
6. Combo / near miss
7. Overclock
8. Focus Mode
9. Patch Pulse
10. Portfolio cards
11. Menus and settings
12. Visual polish
13. Sound polish
```
