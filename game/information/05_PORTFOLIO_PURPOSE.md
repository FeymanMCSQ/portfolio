# Portfolio Purpose

## Why this game exists

Runtime Rush exists for two reasons:

1. To be a fun small browser game.
2. To demonstrate software engineering, interaction design, and product thinking.

The game is not the main portfolio.

The main portfolio website should contain all essential information without requiring gameplay.

## What the game should demonstrate

Runtime Rush can demonstrate:

- frontend engineering
- Canvas rendering
- React/Next.js integration
- TypeScript architecture
- input handling
- game loop design
- state management
- collision detection
- procedural obstacle generation
- animation and polish
- accessibility consideration
- product/design thinking
- ability to scope a creative project

## What the game should not do

The game should not:

- hide important recruiter information
- force anyone to play
- take too long to understand
- become more important than the projects
- become a massive scope trap
- distract from the normal portfolio
- feel like a gimmick with no design discipline

## Portfolio unlocks

Portfolio cards may unlock during play.

Examples:

```txt
Frontend card unlocked
Backend card unlocked
AI/ML card unlocked
Systems card unlocked
Featured project unlocked
Contact card unlocked
```

Each card should be short and link back to normal portfolio sections.

## Recruiter/client experience

A recruiter should be able to:

```txt
visit site
understand who the developer is
see projects
scan skills
contact/download resume
optionally play the game
```

The game is a bonus layer, not a gate.
